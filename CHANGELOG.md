## [0.1.0] - 2026-08-24

### 🚀 Features

- *(m0)* Manifest types, layout rules and the CLI skeleton ([15291d5](https://github.com/murat-akpinar/dotpack/commit/15291d5436b066094a92ff8e6357c0778d425fcc)) — The first code in the repo. M0's whole job is that the two things every later milestone reads — the manifest and the layout — are settled and tested before anything writes to a disk.
- *(pkg)* The package layer, on pacman -T rather than a set difference ([6af5bb4](https://github.com/murat-akpinar/dotpack/commit/6af5bb4bd8e6bc599e2c7ca11116f5edd3342ebc)) — M1's package half. The plan said "installed list via -Qqen / -Qqem" and then subtract; `pacman -T` is one call and it is the one that is correct.
- *(m1)* Switching — the ledger, links, backups and the use/ls/sync/rm verbs ([bf34dad](https://github.com/murat-akpinar/dotpack/commit/bf34dad4361849bffc801eaa6afb79d0029e44ce)) — After this the tool works. `dotpack use example` places the bundle, `use -` goes back, and the machine ends up where it started.
- *(scan)* Reference integrity, both extractors ([213fa9f](https://github.com/murat-akpinar/dotpack/commit/213fa9f6c23c0a214af4fcb3a7169365ec45ed27)) — Every shipped text file is read for the files it points at. A bundle that ships kitty.conf without the catppuccin.conf it includes installs a kitty that errors on every start, and nothing else in the tool would notice.
- *(scan)* The secret scan, and ls runs it on the active bundle ([2f74e26](https://github.com/murat-akpinar/dotpack/commit/2f74e268359f560b0e7aa12f7676284ec094f368)) — Both layers from design.md §6. Shell history is in the deny-list because a public repo that was examined shipped `private_dot_histfile` — chezmoi's `private_` prefix means chmod 600, not "not published".
- *(scan)* WM tables and the command → package chain ([5adbdd2](https://github.com/murat-akpinar/dotpack/commit/5adbdd22b861d57d87386f559afb04a166faeeab)) — deps.rs walks design.md §5's chain and bends where the docs say it bends: a `-Qoq` answer that is not the command name (noctalia-qs providing quickshell) gives way to the portable name when a repo has one, and a file no package owns falls through to `pacman -Si <command>` before `pacman -F <basename>`. That ordering matters on this machine: there is no files database here, and /usr/local/bin/starship still resolves to extra/starship.
- *(collect)* The whole scan, and the bundle it writes ([42fc352](https://github.com/murat-akpinar/dotpack/commit/42fc352c4ab944d9f68c1d012e6994142188bd4d)) — M2. `dotpack collect` reads the machine and `apply::write::write_bundle()` writes the result, so the one-writer invariant holds from the first bundle ever created rather than from the second.
- *(post)* Components → the shareable list, and the bundle's README ([2919bc5](https://github.com/murat-akpinar/dotpack/commit/2919bc5197095208bd7bafe9ff5d80f1cfab3437)) — M3, the adoption lever. `dotpack post [name|path]` renders `[components]` as the list every r/unixporn comment already carries and copies it to the clipboard; `--format reddit|markdown|plain`. `collect` writes the same list into the bundle's README, once, and never regenerates it.
- *(share)* Remote sources, hooks, and the checks a receiver runs first ([ab3f549](https://github.com/murat-akpinar/dotpack/commit/ab3f5490c12330dbb6048c2f38176bb791a804b3)) — `dotpack use github:user/repo` now clones, plans and installs. `source.rs` resolves `github:`/`gitlab:`/git URLs/local paths and refuses a reserved `#variant`; `apply/fetch.rs` does the shallow clone into `.fetching` and only renames it into the store once it has parsed as a bundle, so a repo without a `dotfiles.toml` is rejected and thrown away rather than becoming a broken row in `ls`.
- *(external)* Bundles that place no files, and the manifest collect adds to a chezmoi repo ([68c2de5](https://github.com/murat-akpinar/dotpack/commit/68c2de5a8e754ed82dcf61b01d2e2254cf291508)) — M5. `mode = "external"` installs the packages, shows the roles and touches nothing: the files stay under chezmoi or stow and the user places them. This is the format's main distribution path — adding one file to a repo somebody already keeps is far less to ask than migrating that repo to our layout.
- *(tui)* Nine screens over the verbs M1–M5 already wrote ([7cd7fc5](https://github.com/murat-akpinar/dotpack/commit/7cd7fc5cf32fafea8dc21c9eb16cfb94ae2a5ee2)) — M6. `dotpack` with no arguments now opens the TUI: a bundle list with the active marker and the detached and secret counters, a switch plan that shows a foreign hook's whole source before it can be approved, sync, delete, add, `?` help, and the five-step collect wizard. Every screen calls the function the CLI calls — the plan screen is `apply::plan`, the wizard is `scan::collect` — which is why nine screens fit in 1853 lines with their tests.
- *(example)* The post-install hook, root services and the login shell ([5d1a31d](https://github.com/murat-akpinar/dotpack/commit/5d1a31dcd3fb8c1fa7539c52a7e12b44ca68cd37)) — The one row in the bundle's own "what this still needs" table that was blocked on nothing. Twenty lines, printed in full above the confirmation.
- *(example)* The quickshell UI, the colour pipeline, and a hook that compiles them ([bf5aaf1](https://github.com/murat-akpinar/dotpack/commit/bf5aaf195ab26c8f99313d6333ef5cd18a3e2dea)) — The bundle installs the whole rice now. What kept `scripts/quickshell/` out was 27 MB, of which 23 was nine 1920x1080 screenshots behind a popup that draws them smaller — and the `ignore` line this repo had written down for it was wrong twice over: `guide/**` deletes the popup itself, `guide/previews/**` leaves nine broken image slots. `magick -resize 960x540 -colors 256` is neither, and it is an author's action rather than a field in the format: ignore drops a file, and some files need to be smaller rather than absent.
- *(assets)* Copy them, which nothing did ([54b9e90](https://github.com/murat-akpinar/dotpack/commit/54b9e909b1ee2747821e2b8119bd91892511e2ac)) — `assets` was specified in full since M0 and implemented nowhere: `bundle::assets()` mapped the paths behind an `#[allow(dead_code)]`, and neither sequence had a step that copied anything. A bundle declaring wallpapers had them announced in the plan and then not placed.
- *(pkg)* A PKGBUILD, because on Arch that is what installing means ([f5490c5](https://github.com/murat-akpinar/dotpack/commit/f5490c5b4d9eda58efac956f87e773d61f38ab5d)) — A tool arguing that software on Arch arrives as a package had no way of arriving as one, and a README opening on "install them with one command" did not say how to install it. `dotpack-git`, built and packaged with makepkg before this was committed.
- *(example)* Ship settings.json, the file the five generated configs are generated from ([823e44a](https://github.com/murat-akpinar/dotpack/commit/823e44a98a5dba2d465375c7b7811fc29d654b63)) — Installed on a second machine and looked at, three things were missing at once: the keyboard was us on a tr machine, no custom keybind worked, and no startup program started. One cause.
- *(example)* Ship the shell, the fetch and the editor — the half that was not the WM ([cfa15a0](https://github.com/murat-akpinar/dotpack/commit/cfa15a0eda40d2541493d21765e33b423d168804)) — Installed on the other machine and looked at: fastfetch printed its default output, the shell was a bare fish the hook had just chshed into, and the editor was stock. The manifest names all three as components, so the packages installed and the roles were declared, and not one config directory travelled — `collect` selects the WM's directory and what its config points at, and hyprland.conf does not point at ~/.config/fish.
- *(refs)* A home directory written out in full is a finding ([1a2728d](https://github.com/murat-akpinar/dotpack/commit/1a2728d68745e17afea2a3e5ca1fcd72607f9516)) — Three of the bundle's faults this week were the same shape — a literal `/home/<author>/…` in a shipped file — and nothing was looking for them. `~/` and `$HOME/` mean the receiver's home; `/home/someone/` is wrong on every machine but the one it was typed on, and it is typed on the author's. It gets its own verdict rather than "the bundle does not ship it", which is true and useless: nobody can ship somebody's home directory.

### 🐛 Bug Fixes

- *(collect)* A ticked directory is evidence for its own package ([18c368e](https://github.com/murat-akpinar/dotpack/commit/18c368ebca718ef8dfb443833adde29c2d23df60)) — `collect kitty` wrote a bundle with an empty `[packages]`: every suggestion came from a command a config *launches*, and nothing in `kitty.conf` launches kitty. The bundle shipped a terminal's config and never installed the terminal.
- *(m7)* What a second machine found ([b933888](https://github.com/murat-akpinar/dotpack/commit/b933888315d2d2b93452340d62be4e29f2332709)) — A second Arch box — Hyprland and sway, no AUR helper, no files database — under a throwaway HOME. Five findings, none of them visible on the machine the tool was written on.
- *(refs)* Carry path variables down a file, one finding per missing path ([5a2bdbb](https://github.com/murat-akpinar/dotpack/commit/5a2bdbb37458e0f92dd305cc90a0ea031651a4dd)) — Shipping the example bundle's quickshell directory turned the reference check over on itself. `SCRIPT_DIR="$(dirname …)"` on line 3 and `source "$SCRIPT_DIR/../../caching.sh"` on line 4: the substitution only ever reached inside one line, so three references came back Unresolved and the plan told the receiver a file the bundle ships was missing. Same shape as sway's `set $term foot` in the dependency scan.
- *(assets)* Only report a skip when the file is not the bundle's own ([b0e467e](https://github.com/murat-akpinar/dotpack/commit/b0e467ea9ae275f69abd607e22e9d9ca69d3b403)) — Found on the second machine, switching to the same bundle twice: every asset placed by the previous activation came back as "already there — not written over". A bundle with forty wallpapers reports forty non-events on every switch from then on, which is the failure the reference check already had once, where 38 findings became 13 by reporting one line per missing path.
- *(example)* Seed the wallpaper directory, and stop trusting xdg-user-dir's exit code ([3f687a4](https://github.com/murat-akpinar/dotpack/commit/3f687a4d7e50493f3eaf7c2d7fc47393dc8d6ef8)) — The first end-to-end install on a second machine — clone from GitHub, plan, hook, links — produced `env = WALLPAPER_DIR,` with nothing after it, and an `XDG_PICTURES_DIR` naming the home directory itself. Two faults, both the rice's, neither visible on the machine it was written on.
- *(example)* Seed the wallpaper directory every run, not only when it is empty ([7c45238](https://github.com/murat-akpinar/dotpack/commit/7c45238b0f858e622f268fab009820b8d53b612a)) — Installing onto the machine's real HOME after a run under a throwaway one showed the first version of this seed inheriting the lab's path: `WALLPAPER_DIR` came out naming `~/dp-lab3/Pictures/Wallpapers` on a HOME that had never heard of it.
